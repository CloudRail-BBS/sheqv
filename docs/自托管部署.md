# 自托管部署

> 本文只讲一件事：把这套 Web 端跑在**你自己的服务器**上，不依赖任何托管平台。
>
> 托管发布已下线（原分享链接失效）。当前仓库的自托管入口是 `web/Dockerfile` 与 `web/docker-compose.yml`。

---

## 1. 部署形态

```
                     ┌──────────────────────────────┐
  浏览器 ──TLS──▶ nginx/Caddy ──▶ Next.js (node)  ──▶ $DATA_DIR/*.json
                     └──────────────────────────────┘
                     反代只负责 TLS/压缩/大文件      唯一需要持久化的目录
```

- **一个进程**：Next.js standalone 产物，`node server.js` 即可，不需要 pm2（容器/docker 或 systemd 负责守护）。
- **一个可写目录**：`$DATA_DIR`（默认 `./.data`，容器内 `/data`）。论坛帖子、评论、点赞、后台新增的公约都在这里。
- **无外部依赖**：不需要数据库、对象存储、消息队列。当前实现是文件存储，适合单机；要横向扩容见 §10。

资源占用参考：镜像约 180MB，常驻内存 120–200MB，冷启动 < 1s（standalone 不做运行期编译）。

---

## 2. 前置条件

| 项 | 要求 |
|---|---|
| 系统 | Linux x86_64/arm64（Windows 可用 WSL2 或 Docker Desktop） |
| Node | ≥ 20（裸机部署）；Docker 方式不需要装 Node |
| Docker | ≥ 24，含 compose v2（`docker compose version`） |
| 端口 | 8900（内部），80/443（对外，反代） |
| 磁盘 | ≥ 1GB；数据按实际内容增长（纯 JSON，1 万帖约 10MB） |

## 3. 方式 A：Docker Compose（推荐）

### 3.1 取代码并配置

```bash
git clone <your-repo> blockarena && cd blockarena/web

cp .env.example .env
# 必改：PUBLIC_BASE_URL 换成你的域名；ADMIN_TOKEN 生成一个强口令
openssl rand -base64 24

vi .env
```

`.env` 最小可用内容：

```ini
PUBLIC_BASE_URL=https://arena.example.com
SITE_NAME=方块竞技场

# 会话密钥（不填会自动生成到数据卷，但多实例必须显式统一）
SESSION_SECRET=$(openssl rand -hex 32)

# 人机验证：注册与登录都要过。公网部署强烈建议配置。
GEETEST_ID=你的 Geetest ID
GEETEST_KEY=你的 Geetest Key
```

> **没有默认管理员**。部署完成后打开 `/register`，**第一个注册的账号自动成为管理员**，
> 之后注册的都是普通成员。`ADMIN_TOKEN` 是可选的应急通道，留空即可。

> `PUBLIC_BASE_URL` 必须写**用户浏览器里看到的地址**。写成 `http://localhost:8900` 会导致分享短链、bootstrap 下发的 `shortLinkBase` 全部指错，同时后台 Cookie 不会带 `Secure`。

### 3.2 启动

```bash
docker compose up -d --build
docker compose ps            # 等 healthy
curl -s localhost:8900/api/health
```

期望：

```json
{"ok":true,"service":"blockarena-web","version":"2026.10.20-1","checks":{"dataDir":"ok"}}
```

### 3.3 常规运维

```bash
docker compose logs -f --tail=100 web     # 看日志
docker compose restart web                # 改完 .env 后重启生效
docker compose down                       # 停止（数据卷保留）
docker compose down -v                    # 停止并删数据（慎用）
```

改 `.env` 后**必须** `docker compose up -d` 让容器重建，`restart` 只重启进程、不会重读 compose 层环境变量（`env_file` 变更需 `up -d`）。

## 4. 方式 B：裸机 + systemd

适合不想装 Docker 的机器。

```bash
# 1) 用户与目录
sudo useradd -r -s /usr/sbin/nologin blockarena
sudo mkdir -p /srv/blockarena /srv/blockarena/data /etc/blockarena
sudo chown -R blockarena:blockarena /srv/blockarena

# 2) 构建
cd /srv/blockarena
git clone <your-repo> src && cd src/web
npm ci
NEXT_DIST_DIR=.next npm run build

# 3) 铺 standalone 产物（server.js 需要在根目录）
cp -r .next/standalone/. /srv/blockarena/web/
cp -r .next/static  /srv/blockarena/web/.next/static
cp -r public        /srv/blockarena/web/public

# 4) 配置与权限
sudo cp deploy/blockarena.service /etc/systemd/system/
sudo cp .env.example /etc/blockarena/web.env && sudo vi /etc/blockarena/web.env
# web.env 里 DATA_DIR 指向 /srv/blockarena/data
sudo chown -R blockarena:blockarena /srv/blockarena

# 5) 启动
sudo systemctl daemon-reload
sudo systemctl enable --now blockarena
systemctl status blockarena
curl -s localhost:8900/api/health
```

`deploy/blockarena.service` 已做加固：`ProtectSystem=strict` + `ReadWritePaths=/srv/blockarena/data`，即**只有数据目录可写**，进程被攻破也改不了代码。

## 5. 反向代理与 TLS

### 5.1 nginx

```bash
sudo cp deploy/nginx.conf /etc/nginx/conf.d/arena.conf
sudo vi /etc/nginx/conf.d/arena.conf     # 改 server_name 与证书路径
sudo nginx -t && sudo systemctl reload nginx
```

关键点：

- `client_max_body_size 2100m` —— 对应 `cap.limits.maxUploadBytes = 2GB`，默认 1MB 会让上传直接 413。
- `proxy_request_buffering off` —— 大文件不落反代临时盘。
- `/_next/static/` 单独长缓存（文件名带哈希，可 `immutable`）。
- 健康检查路径**不对外**。

### 5.1 缓存行为（容易踩）

| 资源 | 响应头 | 说明 |
|---|---|---|
| HTML 页面 | `Cache-Control: private, no-cache, no-store` | 页面按 UA 渲染（桌面/移动/微信形态不同），**不允许任何共享缓存存 HTML** |
| `/_next/static/*` | 文件名带内容哈希 | 可 `immutable` 长缓存一年 |
| `/api/v1/bootstrap` | `private, max-age=300` + `ETag` | 客户端协商缓存，304 复用 |

> `Vary` 由 Next 写入 RSC 相关值（`rsc`、`next-router-*`），我们的 `User-Agent` 会被覆盖。
> 因为 HTML 已经是 `private/no-store`，共享缓存根本不会命中，所以不影响正确性——
> **不要**为了"补 Vary"把 HTML 改成可公开缓存，那才会串形态。

### 5.2 Caddy（自动 HTTPS）

```bash
sudo cp deploy/Caddyfile /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

Caddy 会自动申请并续期证书，适合单机小站。

### 5.3 证书

```bash
sudo certbot --nginx -d arena.example.com
```

## 6. 环境变量

全部在 `web/.env.example`，服务端读取，不会进浏览器包。

| 变量 | 默认 | 说明 |
|---|---|---|
| `PUBLIC_BASE_URL` | `http://localhost:8900` | **必填（生产）**。对外根地址，决定短链、`Secure` Cookie、bootstrap endpoints |
| `SESSION_SECRET` | 自动生成 | 会话签名密钥。生成在 `$DATA_DIR/.session-secret`；**多实例必须显式配同一个值** |
| `GEETEST_ID` / `GEETEST_KEY` | 空 | GeeTest v4 人机验证，两个都填才启用。留空跳过校验（仅限内网） |
| `GEETEST_BYPASS_ON_ERROR` | `0` | GeeTest 宕机模式：校验接口不可达时是否放行。默认拒绝 |
| `ADMIN_TOKEN` | 空 | **应急通道**，不是默认管理员。设置后可用 `Bearer` 直接调后台接口，用于忘记密码救急 |
| `ADMIN_USER` | `admin` | 保留字段（当前界面不再使用口令登录） |
| `AFDIAN_USER_ID` / `AFDIAN_TOKEN` | 空 | 爱发电开放 API 凭据，两个都填才启用赞助同步 |
| `AFDIAN_PAGE_URL` | 按 user_id 推导 | 公开赞助页地址，用于 `/sponsors` 的「去爱发电支持」 |
| `SITE_NAME` | `方块竞技场` | 品牌名 |
| `APP_VERSION` | `2026.10.20-1` | 写进 bootstrap `client.version` |
| `DATA_DIR` | `<cwd>/.data` | 数据目录，**唯一需要持久化** |
| `API_BASE` | `/api` | 前端 API 前缀 |
| `WS_URL` | `PUBLIC_BASE_URL` 转 ws + `/ws` | 实时通道地址 |
| `CDN_BASE` | `PUBLIC_BASE_URL` | 静态资源前缀（接 CDN 时改） |
| `SHORT_LINK_BASE` | `PUBLIC_BASE_URL` + `/s` | 分享短链前缀 |
| `ENABLE_DEV_CONSOLE` | prod 下 `0` | 是否开放 `/dev/capabilities` 调试页 |
| `TRUST_PROXY` | `1` | 反代后信任 `X-Forwarded-*` |

> 之前的版本把 `ws/cdn/s.blockarena.example` 写死在代码里，自托管会拿到假地址。现在**全部来自环境变量**，默认按 `PUBLIC_BASE_URL` 同源推导。

## 7. 数据、备份与恢复

### 7.1 数据位置

```
$DATA_DIR/
├── users.json          # 账号（密码为 scrypt 加盐哈希）+ 角色
├── forum.json          # 帖子、评论、点赞
├── agreements.json     # 后台新增的公约
├── sponsors.json       # 赞助者快照（爱发电同步 + 手动录入）
└── .session-secret     # 自动生成的会话密钥（0600）
```

> `users.json` 里 `role` 只有 `admin` / `member`。第一个注册用户拿到 `admin`；
> 需要移交权限时直接改这个字段（改完重启即可，无需迁移脚本）。

内置内容（种子帖子、两份内置公约）在代码里，不占数据目录；所以**丢数据目录 = 丢掉用户产生的内容**，内置内容会自动重建。

写入策略：临时文件 + `rename` 原子替换，进程内写操作串行化。断电不会留下半个 JSON。

### 7.2 备份

```bash
cd web
./deploy/backup.sh backup 14        # 保留最近 14 份，输出到 web/backups/
```

热备份，不需要停服（数据是纯 JSON，几 MB 级别）。

裸机部署：

```bash
tar czf /var/backups/blockarena-$(date +%F).tar.gz -C /srv/blockarena/data .
```

### 7.3 恢复

```bash
./deploy/backup.sh restore backups/blockarena-20261020-193000.tar.gz
```

会清空 `/data` 再解包，然后自动重启。**执行前先手动再备一份当前数据。**

### 7.4 迁移到新机器

备份 → 新机器 `compose up -d` → 恢复。没有别的状态（不依赖本机缓存、不依赖 Redis）。

## 8. 升级与回滚

```bash
cd web
git pull
docker compose up -d --build      # 构建新镜像并切换
curl -s localhost:8900/api/health # 确认健康
```

- 数据卷不受影响（`down` 不删卷，`down -v` 才删）。
- 回滚：`git checkout <上一个 tag> && docker compose up -d --build`。

镜像 tag 建议按版本推进（`docker-compose.yml` 里 `image: blockarena/web:2026.10.20`），方便 `docker images` 里找到上一版直接回退：

```bash
docker compose down
docker tag blockarena/web:2026.10.19 blockarena/web:current
# 或直接用旧 image 启动
```

## 9. 安全检查清单

部署完逐项过，`bash scripts/selfhost-check.sh` 能自动验前 6 项。

- [ ] 已注册首个账号（它自动成为管理员），并在「我的」确认身份徽标是「管理员」
- [ ] 已配置 `GEETEST_ID` / `GEETEST_KEY`；注册页能看到验证码而不是"未配置"提示
- [ ] 未登录访问 `/admin` 显示「后台需要登录」；普通成员访问显示「不是管理员」
- [ ] `SESSION_SECRET` 已设置（单机可留空自动生成，多实例必填）
- [ ] `PUBLIC_BASE_URL` 是 `https://`，Cookie 才会带 `Secure`
- [ ] `/dev/capabilities` 返回 404（`ENABLE_DEV_CONSOLE` 未开）
- [ ] 8900 端口只绑 `127.0.0.1`，不直接对公网
- [ ] `DATA_DIR` 属于运行用户，权限 `750` 左右；不要放在 Web 可访问目录
- [ ] 反代已限制 `client_max_body_size`，且 `/api/health` 不对公网开放
- [ ] 备份任务已挂 cron，且**实际恢复演练过一次**
- [ ] `.env` 权限 `600`，未提交进 Git（`.gitignore` 已排除）
- [ ] 若要多人分权：`ADMIN_TOKEN` 是单口令方案，需换成 OIDC / 反代 SSO（见 §11）

## 10. 已知边界（自托管前必须知道）

| 边界 | 影响 | 处理 |
|---|---|---|
| **文件存储，非数据库** | 多副本部署会各写各的，数据不一致 | 单实例运行；要横向扩容先把 `lib/json-store.ts` 换成 Postgres |
| **写操作串行化只在进程内** | 多进程写同一文件会丢更新 | 同上，单实例 |
| **无真实账号体系** | 当前用户固定「风蚀」，后台是单口令 | 接 OIDC / 自有账号服务 |
| **无对象存储** | 资源上传只有配额校验，没有落地通道 | 接 S3/MinIO，或本地卷 + `CDN_BASE` |
| **无系统推送** | 通知只有站内红点 | 设计即如此（见功能清单 §7） |
| **托管平台的 `sharecode` 不再适用** | 自托管直接访问根路径，不需要查询参数 | 无 |

> 结论：**当前版本适合单机部署、小规模社区使用**。要上多副本/高可用，第一步是把两个 store 换成数据库，第二步是把 Cookie 里的签名迁到服务端会话表。

## 11. 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 容器起来但页面 502 | 进程没监听 `0.0.0.0` | 镜像已设 `HOSTNAME=0.0.0.0`；裸机用 `node server.js` 或 `npm start` |
| 静态资源 404、页面无样式 | standalone 漏拷 `.next/static` | 按 §4 第 3 步补齐 |
| `/api/health` 返回 503 `dataDir: unwritable` | 卷权限不对 | `chown -R 1001:1001 <数据卷>`（镜像内 uid 1001） |
| 上传 413 | 反代 `client_max_body_size` 太小 | 调到 2100m |
| 改 `.env` 不生效 | 只 `restart` 未重建 | `docker compose up -d` |
| 注册页没有验证码 | 未配置 `GEETEST_ID` / `GEETEST_KEY` | 补上两个变量后重建容器 |
| 人机验证一直失败 | 域名未在 GeeTest 后台登记，或 Key 与 ID 不匹配 | 检查 GeeTest 控制台的验证域名与密钥对 |
| 忘记管理员密码 | 无自助找回 | 停服务 → 编辑 `$DATA_DIR/users.json` 删掉该用户 → 重启 → 用原用户名重新注册（若已是唯一账号且不想删，可临时设 `ADMIN_TOKEN` 应急） |
| 所有会话突然失效 | `SESSION_SECRET` 变了，或数据卷丢了 `.session-secret` | 固定 `SESSION_SECRET`，并确保卷持久化 |
| 赞助页一直空 | 没同步过，或爱发电未配置 | 后台「赞助管理 → 立即同步」；`/api/v1/admin/afdian/sync` 会返回具体原因 |
| 同步报 `api_error` | token 错、或开放 API 未开通 | 看返回的 `message`（爱发电原文），核对控制台凭据 |
| 同步报 `unreachable` | 服务器出网被墙/被限 | 放行 `afdian.com:443`，或改用 cron 从可出网的机器触发 |
| 分享链接指向 localhost | `PUBLIC_BASE_URL` 没改 | 改完重建容器 |
| 时间显示偏差 | 容器时区 | 镜像已设 `TZ=Asia/Shanghai`，可覆盖 |

日志：

```bash
docker compose logs -f web          # 容器
journalctl -u blockarena -f         # systemd
```

## 12. 部署后自检

```bash
# 不带口令（后台未启用时用）
bash scripts/selfhost-check.sh https://arena.example.com

# 带口令，会额外验证 401 / 200 / 错误口令
ADMIN_TOKEN='你的口令' bash scripts/selfhost-check.sh https://arena.example.com
```

检查项：健康与数据目录可写、9 个关键页面 200、bootstrap 不含 `example` 占位域名、调试页已关闭、后台鉴权三态、安全响应头。

赞助同步（可选，配了爱发电之后）：

```bash
# 手动一次
curl -X POST https://arena.example.com/api/v1/admin/afdian/sync \
  -H "Authorization: Bearer $ADMIN_TOKEN"

# 每小时自动同步
0 * * * * curl -fsS -X POST https://arena.example.com/api/v1/admin/afdian/sync \
  -H "Authorization: Bearer $ADMIN_TOKEN" >/dev/null
```

> 同步接口用 `ADMIN_TOKEN` 鉴权；不配这个变量就只能用管理员会话在后台点按钮。

功能回归（在本机模拟 standalone 运行，验证镜像里的启动方式）：

```bash
NEXT_DIST_DIR=.next npm run build

# standalone 的静态资源要额外拷进去，镜像里由 Dockerfile 完成
cp -r .next/static .next/standalone/.next/static
cp -r public       .next/standalone/public

DATA_DIR=$PWD/.data PORT=8900 node .next/standalone/server.js &
bash scripts/smoke.sh http://localhost:8900
```

> 注意 `DATA_DIR` 用绝对路径。`node .next/standalone/server.js` 的工作目录是 `.next/standalone`，
> 相对路径会指到那里去。
