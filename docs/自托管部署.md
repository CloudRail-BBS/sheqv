# 自托管部署

> 本文只讲一件事：把这套 Web 端跑在**你自己的服务器**上，不依赖任何托管平台。
>
> 托管发布已下线（原分享链接失效）。**当前形态是三容器**（`web` + `api` + `db`），
> 配置按容器分开放：后端在 `server/compose.yml`，前端在 `web/compose.yml`，
> `deploy/` 只放跨栈的入口脚本，仓库根目录不放任何部署文件。
> 直接从下面 **§0** 看起；§1–§8 是分离前的单进程部署，仅作历史参考。

---

## 0. 前后端分离版（当前形态）

```
nginx ─┬─ /api/*  → api:8080 ─→ db:5432
       └─ 其余     → web:8900 ─→ api:8080（内网取数，走 blockarena-net）
```

nginx 也可以只反代 `web:8900`，由 next 的 `/api/*` rewrites 转发到 `api`；两种都支持。

### 0.1 起服务

> **配置按容器分开放**：`server/compose.yml`（db + api）、`web/compose.yml`（web）。
> `deploy/` 只有跨栈入口脚本，不定义任何服务；仓库根目录没有任何部署文件。

一条命令起全栈：

```bash
cd deploy
./up.sh             # 后端栈 → 等 api 就绪 → 前端栈；缺 server/.env 会自动生成（含构建）
./up.sh --no-build  # 日常重启：用现有镜像，不重建，秒级
```

停止：`./down.sh`（保留数据）· `./down.sh --purge`（连数据卷一起删）。
容器都是 `restart: unless-stopped`，**服务器重启后会自动恢复**，不需要手动 up。

想分开控制（改前端不用动后端）：

```bash
cd server
cp .env.example .env              # 或 ./init-env.sh 自动生成随机密码
docker compose up -d --build      # db + api，同时创建 blockarena-net 网络

cd ../web
cp .env.example .env
docker compose up -d --build      # web 接入上面那个网络
```

**顺序不能反**：`blockarena-net` 由后端栈创建，web 以 `external` 方式接入。
先起 web 会报 `network blockarena-net declared as external, but could not be found`。

两个栈的 project name 不同（`blockarena` / `blockarena-web`），所以
`docker compose down` 只影响自己这一栈，不会误删对方容器。

#### 四个最常见的起步报错

| 报错 | 原因 | 处理 |
|---|---|---|
| `password authentication failed for user "arena"` | 数据卷是**旧密码**初始化的；`POSTGRES_PASSWORD` 只在首次 initdb 生效 | 数据可丢：`cd deploy && ./down.sh --purge`；要保留：`cd server && docker compose exec db psql -U arena -d arena -c "ALTER USER arena PASSWORD '新密码';"` |
| `no configuration file provided: not found` | 当前目录没有 compose 文件 | `cd server` 或 `cd web` 后执行 |
| `-bash: ./up.sh: Permission denied` | 脚本没有执行位（Windows 提交常见） | 立即 `bash up.sh`；或 `chmod +x deploy/*.sh server/*.sh server/scripts/*.sh` |
| `exec: "/usr/bin/tini": no such file or directory` | 镜像 ENTRYPOINT 路径与发行版不符 | 本仓库已修（Debian 用 `/usr/bin/tini`、Alpine 用 `/sbin/tini`，且 Dockerfile 里 `test -x` 构建期自检）。旧缓存镜像需 `docker compose build --no-cache api` |

> 执行位由 git 索引的 mode 记录，`.gitattributes` 表达不了。本仓库所有 `.sh` 已登记为 `100755`；
> 新增脚本时必须补一条 `git update-index --chmod=+x <脚本>`，否则 Linux 上又会出现权限错误。

首次启动 `api` 会自动迁移建表、写入两份内置公约与一条欢迎轮播。

### 0.2 建管理员（空站必做）

```bash
cd server
docker compose exec api /usr/local/bin/arena-api create-admin --username ops --password '<强密码>' --nickname 运维
```

不要靠"谁先注册谁是管理员"——公网可达时会被抢注。建完再去后台把「开放注册」打开。

### 0.3 健康检查

| 检查点 | 命令 | 期望 |
|---|---|---|
| api | `curl -s 127.0.0.1:8860/api/health` | `{"ok":true,...}`，数据库不通返回 503 |
| web | `curl -s -o /dev/null -w '%{http_code}' 127.0.0.1:8900/` | 200 |
| 后端容器 | `cd server && docker compose ps` | db / api 均 healthy |
| 前端容器 | `cd web && docker compose ps` | web healthy |
| 一起看 | `cd deploy && ./doctor.sh` | 状态 + 健康 + 三个服务日志 |

`api` 的 healthcheck 用镜像里自带的 `arena-api healthcheck`（没装 curl）；`web` 探首页。

> **宿主机 8080 常被占用**：`api` 容器内部仍监听 8080，但只发布到 `127.0.0.1:8860`
> （`server/.env` 里的 `API_HOST_PORT` 可改）。服务器上已有的 8080 服务不受影响。

### 0.4 备份（`pg_dump` 自定义格式）

```bash
cd server
./scripts/backup.sh --keep 14 --dir /backup        # 本机没有 pg_dump 时自动走容器
```

- 本机有 `pg_dump` 就连 `DATABASE_URL`；没有则自动 `docker compose exec db pg_dump`。
- 备份后做一次 `pg_restore --list` 校验，失败退出非 0（cron 能报警）。
- 保留最近 N 份，默认 30。

**cron 示例**（每天 03:10，日志留存）：

```cron
10 3 * * * cd /srv/blockarena/server && ./scripts/backup.sh --keep 14 --dir /backup >> /var/log/arena-backup.log 2>&1
```

### 0.5 恢复（会覆盖，必须带 `--yes`）

```bash
cd server
./scripts/restore.sh /backup/arena-20261024-031000.dump --yes
```

脚本会先自动备份当前库（`arena-<时间>.dump`），回滚时再用那份。

**演练记录（2026-10-24，本机 PG 18.6）**：备份 13 张表 / 32KB；
恢复到独立库后 `users 76 / posts 22 / comments 15 / agreements 2 / signatures 45` 与源库逐项一致。

### 0.6 压测

```bash
node server/scripts/loadtest.mjs --base http://127.0.0.1:8860 \
  --path api/v1/posts --concurrency 20 --requests 300
```

只读、无依赖。本机实测（PG 同机、20 并发 × 300）：

| 接口 | RPS | p50 | p95 | p99 |
|---|---|---|---|---|
| `/api/v1/posts` | 744 | 16ms | 47ms | 311ms |
| `/api/v1/auth/state` | 1266 | 11ms | 35ms | 37ms |

> 冷启动第一轮 p95 会到 400ms 以上（建连成本）。连接池已设 `min_connections=2` 常驻，
> 但重启后的第一批请求仍会付这个代价，压测请先预热一轮。

### 0.7 慢查询

```sql
-- 需要 shared_preload_libraries=pg_stat_statements + CREATE EXTENSION
SELECT round(mean_exec_time::numeric, 2) AS ms, calls, query
FROM pg_stat_statements ORDER BY mean_exec_time DESC LIMIT 20;
```

没开扩展时，用 `pg_stat_activity` 看当前长事务：

```sql
SELECT pid, now() - query_start AS dur, state, left(query, 80)
FROM pg_stat_activity WHERE state <> 'idle' ORDER BY dur DESC LIMIT 10;
```

## 1. 部署形态

```
                     ┌──────────────────────────────┐
  浏览器 ──TLS──▶ nginx/Caddy ──▶ Next.js (node)  ──▶ $DATA_DIR/*.json
                     └──────────────────────────────┘
                     反代只负责 TLS/压缩/大文件      唯一需要持久化的目录
```

- **一个进程**：Next.js standalone 产物，`node server.js` 即可，不需要 pm2（容器/docker 或 systemd 负责守护）。
- **一个可写目录**：`$DATA_DIR`（默认 `./.data`，容器内 `/data`）。论坛帖子、评论、点赞、后台新增的公约都在这里。
- **无外部依赖**：不需要数据库、对象存储、消息队列。当前实现是文件存储，适合单机；要横向扩容见 §10。

资源占用参考：镜像约 180MB，常驻内存 120–200MB，冷启动 < 1s（standalone 不做运行期编译）。

## 3. 方式 A：Docker Compose（推荐）

### 3.1 取代码并启动

```bash
git clone <your-repo> blockarena && cd blockarena/web
cp .env.example .env          # 可选：只放进程参数与密钥，见 §6.2
docker compose up -d --build
curl -s localhost:8900/api/health
```

`.env` 只装**进程参数与密钥**（`PORT` / `DATA_DIR` / `SESSION_SECRET` / `ADMIN_TOKEN`）。
站点名、人机验证、爱发电这些业务配置**不写在 .env 里**，在后台填。

不建 `.env` 也能跑：端口与数据目录 compose 已给默认值，会话密钥会自动生成。

### 3.2 首次初始化（注册 + 后台配置）

1. 打开 `http://服务器IP:8900/register` 注册第一个账号 —— **自动成为管理员**
2. 进 `/admin/settings` 按需填写：

| 项 | 说明 |
|---|---|
| 站点名 | 标题、品牌位、页脚 |
| 人机验证 | GeeTest 的 `captcha_id` / `captcha_key`，两个都填才启用 |
| 爱发电 | `user_id` / `token`，用于赞助同步 |
| 开放注册 | 关闭后接口拒绝新注册，已有账号不受影响 |
| 对外地址 | 可留空，留空按请求头自动推导 |

改完立即生效，不用重启容器。

### 3.3 常规运维

```bash
docker compose logs -f --tail=100 web     # 看日志
docker compose restart web                # 改 compose 里的 PORT/DATA_DIR 后重启
docker compose down                       # 停止（数据卷保留）
docker compose down -v                    # 停止并删数据（慎用）
```

改了 compose 里的 `environment:` 后**必须** `docker compose up -d` 重建容器，`restart` 不会重读环境变量。
后台「站点设置」里的项不用重启，改完刷新页面就生效。

## 4. 方式 B：裸机 + systemd

适合不想装 Docker 的机器。

```bash
# 1) 用户与目录
sudo useradd -r -s /usr/sbin/nologin blockarena
sudo mkdir -p /srv/blockarena /srv/blockarena/data /etc/blockarena
sudo chown -R blockarena:blockarena /srv/blockarena

# 2) 构建
cd /srv/blockarena
git clone <your-repo> src && cd src/web
npm ci
NEXT_DIST_DIR=.next npm run build

# 3) 铺 standalone 产物（server.js 需要在根目录）
cp -r .next/standalone/. /srv/blockarena/web/
cp -r .next/static  /srv/blockarena/web/.next/static
cp -r public        /srv/blockarena/web/public

# 4) 配置与权限
sudo cp deploy/blockarena.service /etc/systemd/system/
sudo cp /srv/blockarena/src/web/.env.example /etc/blockarena/web.env
sudo vi /etc/blockarena/web.env
# 只改这几行，其余留空即可：
#   DATA_DIR=/srv/blockarena/data
#   PORT=8900
#   SESSION_SECRET=<openssl rand -hex 32>
# 站点名 / 人机验证 / 爱发电 不写这里，去后台「站点设置」填
sudo chown -R blockarena:blockarena /srv/blockarena

# 5) 启动
sudo systemctl daemon-reload
sudo systemctl enable --now blockarena
systemctl status blockarena
curl -s localhost:8900/api/health
```

`deploy/blockarena.service` 已做加固：`ProtectSystem=strict` + `ReadWritePaths=/srv/blockarena/data`，即**只有数据目录可写**，进程被攻破也改不了代码。

## 5. 反向代理与 TLS

### 5.1 nginx

```bash
sudo cp deploy/nginx.conf /etc/nginx/conf.d/arena.conf
sudo vi /etc/nginx/conf.d/arena.conf     # 改 server_name 与证书路径
sudo nginx -t && sudo systemctl reload nginx
```

关键点：

- `client_max_body_size 2100m` —— 对应 `cap.limits.maxUploadBytes = 2GB`，默认 1MB 会让上传直接 413。
- `proxy_request_buffering off` —— 大文件不落反代临时盘。
- `/_next/static/` 单独长缓存（文件名带哈希，可 `immutable`）。
- 健康检查路径**不对外**。

### 5.1 缓存行为（容易踩）

| 资源 | 响应头 | 说明 |
|---|---|---|
| HTML 页面 | `Cache-Control: private, no-cache, no-store` | 页面按 UA 渲染（桌面/移动/微信形态不同），**不允许任何共享缓存存 HTML** |
| `/_next/static/*` | 文件名带内容哈希 | 可 `immutable` 长缓存一年 |
| `/api/v1/bootstrap` | `private, max-age=300` + `ETag` | 客户端协商缓存，304 复用 |

> `Vary` 由 Next 写入 RSC 相关值（`rsc`、`next-router-*`），我们的 `User-Agent` 会被覆盖。
> 因为 HTML 已经是 `private/no-store`，共享缓存根本不会命中，所以不影响正确性——
> **不要**为了"补 Vary"把 HTML 改成可公开缓存，那才会串形态。

### 5.2 Caddy（自动 HTTPS）

```bash
sudo cp deploy/Caddyfile /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

Caddy 会自动申请并续期证书，适合单机小站。

### 5.3 证书

```bash
sudo certbot --nginx -d arena.example.com
```

## 6. 配置在哪

### 6.1 后台设置（推荐，改完立即生效）

`/admin/settings`，存在 `$DATA_DIR/settings.json`，**只记录被改过的项**：

| 项 | 说明 |
|---|---|
| 站点名 | 标题、品牌位、页脚 |
| 对外地址 | 可留空；留空按请求头（Host / X-Forwarded-Proto）自动推导 |
| GeeTest `captcha_id` / `captcha_key` | 两个都填才启用，注册与登录都会校验 |
| 爱发电 `user_id` / `token` / 主页 | 两个都填才启用赞助同步 |
| 开放注册 | 关闭后注册接口拒绝，已有账号不受影响 |
| 首页公告 | 是否在首页右栏显示最新公告 |

优先级：`settings.json` > 环境变量 > 代码默认。清掉某项即回落环境变量。

### 6.2 留在 `.env` 里的（进程参数与密钥）

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `8900` | compose / systemd 里已给默认值 |
| `DATA_DIR` | `./.data`（容器 `/data`） | 数据卷挂载点 |
| `SESSION_SECRET` | 自动生成 | 不配会自动生成到 `$DATA_DIR/.session-secret`；**多实例才需要显式统一** |
| `ADMIN_TOKEN` | 空 | **应急通道**，不是默认管理员。用于忘记密码时用 Bearer 调后台接口 |
| `PUBLIC_BASE_URL` | 空 | 后台「对外地址」的环境变量版本；一般不填，自动推导 |
| `SITE_NAME` | 方块竞技场 | 后台「站点名」的环境变量版本 |
| `GEETEST_ID` / `GEETEST_KEY` 等 | 空 | 后台同名项的环境变量版本，仅在"配置即代码"时使用 |
| `ENABLE_DEV_CONSOLE` | 生产关 | 设为 `1` 才开放 `/dev/capabilities` |

> 这些是**启动期参数与密钥**：改了要重启进程，或者不该落在数据卷里。
> 业务配置（站点名 / 人机验证 / 爱发电 / 注册开关）放后台，改完立即生效。
>
> 环境变量仍然可以当默认值用：后台那一项留空时，会回落同名环境变量。
> 所以「配置即代码」也可行 —— 但要清楚后台一旦填了就以后台为准。

## 7. 数据、备份与恢复

### 7.1 数据位置

```
$DATA_DIR/
├── users.json          # 账号（密码为 scrypt 加盐哈希）+ 角色
├── forum.json          # 帖子、评论、点赞
├── agreements.json     # 后台新增的公约
├── sponsors.json       # 赞助者快照（爱发电同步 + 手动录入）
└── .session-secret     # 自动生成的会话密钥（0600）
```

> `users.json` 里 `role` 只有 `admin` / `member`，第一个注册用户拿到 `admin`；
> 另外两个字段由程序维护：`notifReadAt`（站内信已读水位，毫秒）与 `banned`（封禁标记）。
> 需要移交权限时直接改 `role` 即可；封禁建议走后台，因为那里有"不能锁死最后一个管理员"的保护。

内置内容（种子帖子、两份内置公约）在代码里，不占数据目录；所以**丢数据目录 = 丢掉用户产生的内容**，内置内容会自动重建。

写入策略：临时文件 + `rename` 原子替换，进程内写操作串行化。断电不会留下半个 JSON。

### 7.2 备份

```bash
cd web
./deploy/backup.sh backup 14        # 保留最近 14 份，输出到 web/backups/
```

热备份，不需要停服（数据是纯 JSON，几 MB 级别）。

裸机部署：

```bash
tar czf /var/backups/blockarena-$(date +%F).tar.gz -C /srv/blockarena/data .
```

### 7.3 恢复

```bash
./deploy/backup.sh restore backups/blockarena-20261020-193000.tar.gz
```

会清空 `/data` 再解包，然后自动重启。**执行前先手动再备一份当前数据。**

### 7.4 迁移到新机器

备份 → 新机器 `compose up -d` → 恢复。没有别的状态（不依赖本机缓存、不依赖 Redis）。

## 8. 升级与回滚

升级只换代码，**不动数据**。`$DATA_DIR` 里的账号、帖子、公约、赞助、公告、设置
都保留；新版本加的字段是增量写入，旧数据不需要迁移脚本。

### 8.1 先备份（一分钟，别省）

```bash
cd web
./deploy/backup.sh backup 7        # Docker：打成 backups/blockarena-*.tar.gz
# 裸机：
# tar czf ~/blockarena-$(date +%F).tar.gz -C /srv/blockarena/data .
```

### 8.2 Docker Compose

```bash
cd web
git pull
docker compose up -d --build      # 重新构建镜像并切换容器
docker compose ps                 # 等 healthy
curl -s localhost:8900/api/health
```

- 数据卷 `blockarena-data` 不受影响（`down` 不删卷，`down -v` 才删）。
- `.env` 不在仓库里，`git pull` 不会覆盖你的 `SESSION_SECRET` / `ADMIN_TOKEN`。
- 后台「站点设置」里的配置存于数据卷，升级后照旧生效。

### 8.3 裸机 + systemd

```bash
cd /srv/blockarena/src
git pull
cd web
npm ci                            # 依赖有变时保险起见跑一次
NEXT_DIST_DIR=.next npm run build

# 覆盖产物（server.js / static / public）
cp -r .next/standalone/. /srv/blockarena/web/
cp -r .next/static       /srv/blockarena/web/.next/static
cp -r public             /srv/blockarena/web/public
sudo chown -R blockarena:blockarena /srv/blockarena

sudo systemctl restart blockarena
systemctl status blockarena --no-pager
curl -s localhost:8900/api/health
```

> `ProtectSystem=strict` 下 `/srv/blockarena/web` 对进程只读，但**部署用户仍可写入**，
> 上面的 `cp` 用普通用户执行即可（必要时加 `sudo`）。

### 8.4 更新后自检（30 秒）

```bash
curl -s localhost:8900/api/health          # {"ok":true,...}
ADMIN_TOKEN=xxx bash scripts/selfhost-check.sh https://你的域名   # 26 项体检
```

页面上确认三处：

1. `/admin/settings` 能看到「站点标识文字 / 标识图片地址」——说明是这版代码
2. 顶栏 Logo 正常，右侧账号旁有头衔徽标
3. `/sponsors` 与侧栏「支持我们」按钮可达

浏览器如果还是旧样式，`Ctrl+Shift+R` 强制刷新一次（RSC 载荷会被缓存）。

### 8.5 回滚

```bash
git log --oneline -5              # 找到上一版提交
git checkout <commit>
docker compose up -d --build      # 或 systemd 那套重新 build + restart
```

数据向后兼容：新版本只**增加**字段（如 `title`、`logoText`），旧版本读到时忽略，
所以回滚不会丢数据。真要彻底还原，再用 8.1 的备份恢复。

### 8.6 常见升级问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `git pull` 报 `next-env.d.ts` / `tsconfig.json` 冲突 | 本地跑过 `next dev`，Next 自动改了这两个文件 | `git checkout -- web/next-env.d.ts web/tsconfig.json` 后重新 pull |
| 构建报 `EPERM` / 卡在 Compiling | 本机文件守卫或残留产物目录（Windows 常见） | 删掉 `web/.dist` 后重试；Linux 上一般不会遇到 |
| 更新后页面样式错乱 | 浏览器缓存了旧 CSS / RSC | `Ctrl+Shift+R`；反代若开了长缓存，清一次 CDN |
| 后台少了新选项 | 镜像没重建，跑的还是旧容器 | `docker compose up -d --build`，别只 `restart` |
| 登录状态全掉 | 换了 `SESSION_SECRET`，或数据卷没挂住 | 固定 `SESSION_SECRET`，确认卷仍在 |

## 9. 安全检查清单

部署完逐项过，`bash scripts/selfhost-check.sh` 能自动验前 6 项。

- [ ] 已注册首个账号（它自动成为管理员），并在「我的」确认身份徽标是「管理员」
- [ ] 已配置 `GEETEST_ID` / `GEETEST_KEY`；注册页能看到验证码而不是"未配置"提示
- [ ] 未登录访问 `/admin` 显示「后台需要登录」；普通成员访问显示「不是管理员」
- [ ] `SESSION_SECRET` 已设置（单机可留空自动生成，多实例必填）
- [ ] 走 https 时反代透传了 `X-Forwarded-Proto: https`（Cookie 的 `Secure` 按它判断）
- [ ] `/dev/capabilities` 返回 404（`ENABLE_DEV_CONSOLE` 未开）
- [ ] 8900 端口只绑 `127.0.0.1`，不直接对公网
- [ ] `DATA_DIR` 属于运行用户，权限 `750` 左右；不要放在 Web 可访问目录
- [ ] 反代已限制 `client_max_body_size`，且 `/api/health` 不对公网开放
- [ ] 备份任务已挂 cron，且**实际恢复演练过一次**
- [ ] `/etc/blockarena/web.env` 与 `web/.env` 权限 `600`，且未被提交进 Git（`.gitignore` 已排除）
- [ ] 若要多人分权：`ADMIN_TOKEN` 是单口令方案，需换成 OIDC / 反代 SSO（见 §11）

## 10. 已知边界（自托管前必须知道）

| 边界 | 影响 | 处理 |
|---|---|---|
| **文件存储，非数据库** | 多副本部署会各写各的，数据不一致 | 单实例运行；要横向扩容先把 `lib/json-store.ts` 换成 Postgres |
| **写操作串行化只在进程内** | 多进程写同一文件会丢更新 | 同上，单实例 |
| **无真实账号体系** | 当前用户固定「风蚀」，后台是单口令 | 接 OIDC / 自有账号服务 |
| **无对象存储** | 资源上传只有配额校验，没有落地通道 | 接 S3/MinIO，或本地卷 + `CDN_BASE` |
| **无系统推送** | 通知只有站内红点 | 设计即如此（见功能清单 §7） |
| **托管平台的 `sharecode` 不再适用** | 自托管直接访问根路径，不需要查询参数 | 无 |

> 结论：**当前版本适合单机部署、小规模社区使用**。要上多副本/高可用，第一步是把两个 store 换成数据库，第二步是把 Cookie 里的签名迁到服务端会话表。

## 11. 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 容器起来但页面 502 | 进程没监听 `0.0.0.0` | 镜像已设 `HOSTNAME=0.0.0.0`；裸机用 `node server.js` 或 `npm start` |
| 静态资源 404、页面无样式 | standalone 漏拷 `.next/static` | 按 §4 第 3 步补齐 |
| `/api/health` 返回 503 `dataDir: unwritable` | 卷权限不对 | `chown -R 1001:1001 <数据卷>`（镜像内 uid 1001） |
| 上传 413 | 反代 `client_max_body_size` 太小 | 调到 2100m |
| 改 compose 环境变量不生效 | 只 `restart` 未重建 | `docker compose up -d` |
| 后台改了配置但页面没变 | 浏览器缓存了 RSC payload | 强制刷新（Ctrl+Shift+R） |
| 注册页没有验证码 | 未配置 `GEETEST_ID` / `GEETEST_KEY` | 补上两个变量后重建容器 |
| 人机验证一直失败 | 域名未在 GeeTest 后台登记，或 Key 与 ID 不匹配 | 检查 GeeTest 控制台的验证域名与密钥对 |
| 忘记管理员密码 | 无自助找回 | 停服务 → 编辑 `$DATA_DIR/users.json` 删掉该用户 → 重启 → 用原用户名重新注册（若已是唯一账号且不想删，可临时设 `ADMIN_TOKEN` 应急） |
| 所有会话突然失效 | `SESSION_SECRET` 变了，或数据卷丢了 `.session-secret` | 固定 `SESSION_SECRET`，并确保卷持久化 |
| 用户登录后立刻又被登出 | 账号被后台封禁（`banned=true`） | 后台「用户」页解封，或改 `users.json` |
| 站内信未读数不消 | 只统计别人在你帖子下的评论；自己的评论不通知自己 | 点顶栏面板或通知页的「全部已读」 |
| 赞助页一直空 | 没同步过，或爱发电未配置 | 后台「赞助管理 → 立即同步」；`/api/v1/admin/afdian/sync` 会返回具体原因 |
| 同步报 `api_error` | token 错、或开放 API 未开通 | 看返回的 `message`（爱发电原文），核对控制台凭据 |
| 同步报 `unreachable` | 服务器出网被墙/被限 | 放行 `afdian.com:443`，或改用 cron 从可出网的机器触发 |
| 分享链接指向 localhost | 反代未透传 Host，或在后台「对外地址」写了 localhost | 清空该字段让系统自动推导，并检查 `proxy_set_header Host` |
| 时间显示偏差 | 容器时区 | 镜像已设 `TZ=Asia/Shanghai`，可覆盖 |

日志：

```bash
docker compose logs -f web          # 容器
journalctl -u blockarena -f         # systemd
```

## 12. 部署后自检

```bash
# 不带口令（后台未启用时用）
bash scripts/selfhost-check.sh https://arena.example.com

# 带口令，会额外验证 401 / 200 / 错误口令
ADMIN_TOKEN='你的口令' bash scripts/selfhost-check.sh https://arena.example.com
```

检查项：健康与数据目录可写、9 个关键页面 200、bootstrap 不含 `example` 占位域名、调试页已关闭、后台鉴权三态、安全响应头。

赞助同步（可选，配了爱发电之后）：

```bash
# 手动一次
curl -X POST https://arena.example.com/api/v1/admin/afdian/sync \
  -H "Authorization: Bearer $ADMIN_TOKEN"

# 每小时自动同步
0 * * * * curl -fsS -X POST https://arena.example.com/api/v1/admin/afdian/sync \
  -H "Authorization: Bearer $ADMIN_TOKEN" >/dev/null
```

> 同步接口用 `ADMIN_TOKEN` 鉴权；不配这个变量就只能用管理员会话在后台点按钮。

功能回归（在本机模拟 standalone 运行，验证镜像里的启动方式）：

```bash
NEXT_DIST_DIR=.next npm run build

# standalone 的静态资源要额外拷进去，镜像里由 Dockerfile 完成
cp -r .next/static .next/standalone/.next/static
cp -r public       .next/standalone/public

DATA_DIR=$PWD/.data PORT=8900 node .next/standalone/server.js &
bash scripts/smoke.sh http://localhost:8900
```

> 注意 `DATA_DIR` 用绝对路径。`node .next/standalone/server.js` 的工作目录是 `.next/standalone`，
> 相对路径会指到那里去。
