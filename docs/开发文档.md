## 2. 本地运行

```bash
cd web
npm install
npm run dev            # http://localhost:8900（端口写死在 dev 脚本里，改就改 package.json）
```

生产构建（本机有文件删除守卫时，用新的产物目录并提高阈值）：

```bash
CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD=5000 \
NEXT_DIST_DIR=.dist npx next build

npm start              # 默认 8900；PORT=9000 npm start 可临时换
npm run start:standalone   # 跑镜像里的 server.js，验证部署形态
```

> 启动走 `scripts/start.mjs` 而不是直接 `next start -p ${PORT:-8900}`：
> npm 在 Windows 上用 cmd.exe 执行脚本，`${VAR:-default}` 不展开，会传字面量给 next。
> 这层包装同时给 `--standalone` 用（跑镜像里的 `server.js`）。

> 本机踩坑：产物目录第一次建时会在 `.dist/trace` 报一次 `EPERM`，重试一次即可；重复构建会因批量删除被守卫拦截。
> 日常迭代用 `next dev` 即可，不需要每次构建。

自托管部署（Docker）三步，详见 [`自托管部署.md`](./自托管部署.md)：

```bash
cp .env.example .env               # 改 PUBLIC_BASE_URL / ADMIN_TOKEN
docker compose up -d --build
curl -s localhost:8900/api/health  # {"ok":true,...}
```

## 3. 一次请求发生了什么

```
浏览器
  │  GET /  (User-Agent / sec-ch-ua-mobile / cookies: theme, __form)
  ▼
middleware.ts
  │  detectRuntime() → { runtime:'web', form:'desktop|mobile', isWeChat }
  │  写响应头 x-runtime / x-form / x-wechat / Vary
  ▼
app/layout.tsx  (server)
  │  getRequestCaps()  ← React cache，每请求只解析一次
  │  getTheme()        ← 读 theme cookie
  │  输出 <html data-theme data-form data-runtime data-wechat>
  ▼
页面 (server component)
  │  const caps = await getRequestCaps()
  │  用 caps.capabilities.* / caps.limits.* 决定渲染
  ▼
客户端组件（'use client'）
     useCap() 只读消费；不解析 UA，不改能力
```

**不要**在客户端重新判断 UA、窗口宽度来改功能 —— 那会绕过 fail-closed 规则。

## 4. 端能力：三个概念

| 概念 | 取值 | 谁决定 | 影响 |
|---|---|---|---|
| `runtime` | web / android / ios | 构建产物 + 服务端 UA | 契约里的"端" |
| `form` | desktop / mobile | UA / CH / dev cookie | **只影响布局**，靠 CSS 断点落地 |
| `isWeChat` | true / false | UA 含 `MicroMessenger` | 唯一的能力修正因子 |

合并顺序：`DEFAULTS[runtime]` → 微信覆盖（**直接改值**）→ 服务端下发（**AND，只能关**）。

### 加一个能力键

1. `lib/capabilities.ts` 的 `Capabilities` 加字段，四张默认表都补上（web / android / ios；微信覆盖里也补）。
2. `contracts/README.md` §4 矩阵补一行；`bootstrap.openapi.yaml` 的 `Capabilities` 补同名属性。
3. 页面上用 `caps.capabilities.xxx` 判断，不要写 `if (form === 'mobile')`。
4. 顺序不能反：**先发客户端，再让服务端下发**，否则老客户端读到 `undefined`。

### 加一个配额

`Limits` 加字段 → 默认值 → `buildCapabilities` 里 `pick()` 取 `min` → 矩阵同步。

## 5. 页面约定

- 两栏骨架：`<div className="cols"><div className="col-main">…</div><aside className="rail">…</aside></div>`。
- 列表为空时也要有卡片边界，不要裸文本。
- 卡片：`card` + `card-pad`；行内小卡用 `rail-card`。
- 数字统一 `font-variant-numeric: tabular-nums`（`.num` / `.mono`）。
- 表格数字列加 `className="num"` 右对齐。
- 破坏性操作（解散、下架、仲裁）一律二次确认弹窗（`.modal-mask` / `.modal`）。

## 6. 主题（明暗）

- 深色为默认，浅色是**独立色值**不是反色。
- **黑白为主**：深色背景 `#0a0a0b → #1d1d21` 中性灰阶，强调色 `--accent` 为近白 `#f4f4f5`，
  主按钮白底黑字（`--btn-bg` / `--accent-ink`）。浅色主题反过来，黑底白字。
- **只有 `--danger` 保留彩色**（#f87171 / #dc2626）——删除、封禁、错误需要可识别的语义色。
- 颜色只走 CSS 变量；组件里不要再写死十六进制。唯一例外是爱发电头像（外链图片）。
- 主题写在 cookie 里，SSR 直接输出 `<html data-theme>`，首屏不闪。

## 8. 数据层与接 API 的路径

现在全部来自 `src/lib/data.ts` 的内存 mock。接后端时按这个顺序：

1. `/api/v1/bootstrap` 已经就绪（含 ETag），客户端用它拿能力与配额。
2. 把 `data.ts` 的数组换成 `fetch` + `cache()`，函数签名保持 `async`，页面不需要改结构。
3. 写接口统一带幂等键（`Idempotency-Key`），比赛提交带 `version` 做乐观锁。

### 8.1 公约签署（签名存 cookie）

- 数据与解析：`lib/agreements.ts`（纯数据，客户端可 import）。
- 服务端读签名：`lib/agreement-state.ts` 的 `getSignatures()` / `isTrustSigned()`。
- 写入：`POST /api/v1/agreements/sign`，写 httpOnly cookie `ag_trust` / `ag_community`，值为 `版本.时间戳`。
- 版本即约束：cookie 里的版本与 `AGREEMENTS[x].version` 不一致 → `signed=false, stale=true`，页面提示重新签署。
- 限制放在**服务端渲染分支**里（如比赛详情页的 `!trustSigned`），前端遮罩不算数。
- 新增一份公约：`AGREEMENTS` 加一项 → 页面与 `/me` 自动出现 → 在需要的地方调用对应的 `isXxxSigned()`。

> 换成真实后端时，把 cookie 校验替换成 `GET /api/v1/agreements/signatures`，其余分支不动。

### 8.2 后台新增公约

- 存储：`lib/agreement-store.ts`，内置两份 + `$DATA_DIR/agreements.json`（后台新增）。
- 落盘：`lib/json-store.ts` 统一提供「临时文件 + rename 原子写」与进程内串行队列；并发新增不会互相覆盖，断电不会留半个 JSON。
- 接口：`GET/POST/PATCH/DELETE /api/v1/admin/agreements`，四个方法都先过 `checkAdminRequest()`。
  - POST 入参 `{ title, version, scope, summary, gate, clauses[] }`，校验失败返回 422 带中文原因。
  - 内置 id `trust` / `community` 禁止停用与删除（403）。
- 页面：`/admin/agreements` + `components/agreement-admin.tsx`（客户端表单 + 表格操作，成功后 `router.refresh()`）。
- 生效链路不用改：`/agreements`、`/me`、签署接口都走 `listActive()` / `getAgreement()`，新增即出现。
- 上生产：把 store 换成 DB 即可，函数签名（list / get / create / setActive / remove）保持不变。

### 8.3 文件存储的边界

| 事实 | 后果 |
|---|---|
| 数据在 `$DATA_DIR`，纯 JSON | 备份 = 打包一个目录，迁移 = 拷目录 |
| 写操作串行化**只在单进程内** | 多实例共享同一目录会丢更新 → 只支持单实例 |
| 无数据库、无 Redis | 没有横向扩容能力；要扩容先换 `json-store` |

### 8.4 站点设置（环境变量搬进后台）

有些值只改代码注释不够，运营必须能自己改，所以做成运行时设置。

| 项 | 存哪 | 生效时机 |
|---|---|---|
| 站点名 / GeeTest ID+KEY / 爱发电 user_id+token+主页 / 开放注册 / 首页公告开关 | `$DATA_DIR/settings.json` | **立即** |
| `PUBLIC_BASE_URL` / `DATA_DIR` / `PORT` | 仅环境变量 | 重启 |
| `SESSION_SECRET` / `ADMIN_TOKEN` | 仅环境变量 | 重启 |

优先级：`settings.json` > 环境变量 > 代码默认值。`settings.json` **只存被后台改过的键**，
所以"清掉某个键就回落环境变量"，后台每项旁边都有「恢复环境变量」按钮。

`lib/settings.ts` 只暴露 `getSettings()` / `updateSettings()` / `resetSetting()`；
`geetest.ts` 与 `afdian.ts` 都改成 async 从这里取值，不再直接读 `config`。

**为什么不把密钥也放后台**：`SESSION_SECRET` 与 `ADMIN_TOKEN` 一旦落 JSON，
备份或误提交就会泄漏；这两项留在 `.env` 里由运维管理。
GeeTest KEY 与爱发电 token 无法回避（运营要自己填），后台页面上明确写了"明文存于数据卷"。

### 8.5 账号体系

```
注册 ──► GeeTest 服务端校验 ──► users.json（第一个用户 role=admin）
                                   │
登录 ──► scrypt 校验 ──────────────┴──► 签名 Cookie（ba_session）
                                          │
                                          └─► getCurrentUser() → 页面 / 接口
```

| 关注点 | 实现 | 位置 |
|---|---|---|
| 密码哈希 | scrypt N=16384 r=8 p=1，16 字节随机盐，参数写进哈希串（可平滑提强度） | `lib/users.ts` |
| 会话 | 无状态签名 Cookie：`userId.exp.hmac`，7 天 | `lib/session.ts` |
| 会话密钥 | `SESSION_SECRET`，缺省自动生成 `$DATA_DIR/.session-secret` | `lib/session.ts` |
| 当前用户 | `getCurrentUser()`，每请求一次（React cache） | `lib/current-user.ts` |
| 首个管理员 | `createUser()` 在同一串行区间内判断 `users.length === 0`，并发也只有一个 admin | `lib/users.ts` |
| 人机验证 | 客户端拿票据 → 服务端算 `sign_token` 换结论 | `lib/geetest.ts` + `components/geetest.tsx` |

**几个不能改错的点：**

1. **作者只能来自会话**。`POST /api/v1/posts` 忽略客户端传的 `author`，用 `user.nickname` —— 否则谁都能冒充别人发帖。
2. **人机验证必须服务端校验**。前端的 `onSuccess` 只代表"人完成了交互"，票据仍要拿去 `gcaptcha4/validate` 换结论。
3. **没有默认管理员**。不要为了"方便"加一个内置账号；首次部署引导到 `/register` 即可。
4. **`ADMIN_TOKEN` 是应急通道**，只在显式配置时生效，不参与日常登录。

### 8.6 赞助者（爱发电）

```
爱发电开放 API ──sync(admin/cron)──► sponsors.json 快照 ──只读──► /sponsors
                                          ▲
                                    后台手动录入
```

| 关注点 | 实现 | 位置 |
|---|---|---|
| 签名 | `md5(token + "params" + params + "ts" + ts + "user_id" + user_id)` | `lib/afdian.ts` |
| 拉取 | `query-sponsor` 自动翻页（每页 20，最多 10 页） | `lib/afdian.ts` |
| 快照 | `sponsors.json`：`sponsors[] / syncedAt / lastCount` | `lib/sponsor-store.ts` |
| 公开页 | 只读快照，不打接口——赞助接口挂了不能拖垮页面 | `app/sponsors/page.tsx` |
| 管理 | `/admin/sponsors`：同步、手动录入、隐藏、删除 | `components/sponsor-admin.tsx` |

**同步的合并语义**（改这块务必看）：

- 以爱发电 `user_id` 为主键覆盖 `amount / planTitle / lastPayAt`；
- 原有的 `hidden` 按 id 保留——隐藏是运营决定，不该被下次同步抹掉；
- `source: 'manual'` 的条目原样保留，不参与覆盖也不被删除；
- 手动条目只能「删除」，爱发电条目只能「隐藏」（重同步就会回来，删了没意义）。

### 8.7 公告与轮播

两者都是"后台改、前台立刻变"的内容，不再硬编码在代码里。

```
公告：$DATA_DIR/announcements.json   → /announcements、/announcements/[id]、首页右栏
轮播：$DATA_DIR/slides.json         → 首页 <Carousel slides={...} />
```

- **公告**：`kind` 只有规则 / 版本 / 活动 / 系统；`pinned` 置顶；`published=false` 是草稿，
  前台列表与详情都看不到（详情页 `notFound()`）。
- **轮播**：每张可设 `bgColor`（预设色板 + 自定义 hex）或 `bgImage`（URL，优先），
  另有 `textTone` 控制文字明暗。`lib/slide-store.ts` 的 `safeHref()` / `safeColor()`
  会挡掉 `javascript:` 之类的注入；`slides.json` 不存在时用内置的三张引导，一旦后台保存过就以文件为准
  （**删光也能生效**，不会被默认值顶回来）。
- 全部轮播停用后，首页直接不渲染这一块，不留空位。

### 8.8 站内信

```
评论/待确认比赛 ──聚合──► getNotifications(user) ──► 顶栏面板 + /notifications
                                    ▲
                        users.json 的 notifReadAt（已读水位）
```

- 聚合：`lib/notifications.ts`。评论来自 `forum-store.listNotifications(excludeAuthor)`（顺手改成一次读盘建索引，避免逐条 `getPost`）。
- 未读：`at > user.notifReadAt`；只算评论，比赛/争议恒为"待处理"，不随已读消失。
- 已读：`POST /api/v1/notifications/read`，把 `notifReadAt` 往后推（`Math.max`，不回退）。
- UI：顶栏 `NotificationBell` 首屏数据由 layout 传入，打开时再拉一次；通知页复用同一聚合函数。

### 8.9 后台鉴权

- `lib/admin-auth.ts` 两个入口：`getAdminGate()`（页面）、`checkAdminRequest(req)`（路由）。
- 判定依据是 `users.json` 里的 `role === 'admin'`；`ADMIN_TOKEN` 只在显式配置时作为应急通道。
- 要按角色细分（审核 / 仲裁），把这两个函数换成带权限位的 IdP，调用点不用动。

## 9. 管理后台

| 页面 | 能力 | 依赖 |
|---|---|---|
| `/admin` | 真实统计（用户/帖子/评论/赞助）、最近注册、最近帖子、待处理比赛 | `listUsers` `forumStats` `getSnapshot` |
| `/admin/users` | 改角色、封禁/解封、删除 | `api/v1/admin/users` |
| `/admin/posts` | 筛选、删除（连带评论与点赞） | `api/v1/admin/posts` |
| `/admin/announcements` | 发布 / 编辑 / 置顶 / 转草稿 / 删除 | `api/v1/admin/announcements` |
| `/admin/slides` | 轮播增删改，背景色或背景图、文字明暗、排序 | `api/v1/admin/slides` |
| `/admin/settings` | 站点名、GeeTest、爱发电、注册开关、首页公告开关 | `api/v1/admin/settings` |
| `/admin/agreements` | 新增/停用/删除公约 | `api/v1/admin/agreements` |
| `/admin/sponsors` | 同步爱发电、手动录入、隐藏/删除 | `api/v1/admin/sponsors` |

**三条防锁死规则**（`api/v1/admin/users` 里实现，不要绕过）：

1. 不能改自己的角色、封禁自己、删自己；
2. 任何操作后必须至少剩一个**可用**管理员（`role=admin && !banned`）；
3. 应急口令（无会话）可以操作，但同样受规则 2 约束。

封禁是**全局生效**的：`getCurrentUser` 解析会话后检查 `banned`，被禁账号的旧 Cookie 直接作废，登录接口返回 403 `account_banned`。

| 现象 | 原因 / 处理 |
|---|---|
| 页面样式全丢 | 检查 `globals.css` 是否被 `layout.tsx` import；dev 下改 CSS 需等 HMR |
| 主题切换后刷新又变回去 | cookie 没写成功（`path=/` 缺失或被浏览器拦） |
| 移动端看到桌面布局 | `--window-size` 太小但 headless 有最小窗宽（约 500px）；真机不受影响 |
| 构建卡住不动 | 产物目录被文件守卫拦批量删除；换新 `NEXT_DIST_DIR` 或提高阈值 |
| 微信内判断错 | 看响应头 `x-wechat` 与 `x-form`，再看 `/dev/capabilities` 的 source |
| 后台在手机上打不开 | 已取消 403；若仍 403，检查是否有旧 middleware 缓存 |
| 部署后 `/api/health` 返回 503 | 数据目录不可写（卷权限）。容器内 uid 是 1001：`chown -R 1001:1001 <卷>` |
| 上传报 413 | 反代 `client_max_body_size` 太小，调到 2100m |
| 分享链接指向 localhost | `PUBLIC_BASE_URL` 没改；改完要 `docker compose up -d` 重建，`restart` 不重读 env_file |
| 后台一直停在登录页 | `ADMIN_TOKEN` 里的 `$`、空格被 shell 展开；用单引号包值或用 `openssl rand -base64 24` |
| `node server.js` 起来但页面无样式 | standalone 漏拷 `.next/static` 与 `public` |
| 接口 500：`cookies was called outside a request scope` | 在 Route Handler 里调了被 `cache()` 包住的 `getCurrentUser()` | 改用 `getCurrentUserFrom(req)` / `isCommunitySignedFrom(req)` |
| 注册页没有验证码 | `GEETEST_ID` / `GEETEST_KEY` 没配 | 补上后重建；未配时会跳过校验并在页面提示 |
| 一直是「第一个用户」提示 | 数据目录被清空或卷没挂住 | 检查 `DATA_DIR` 与卷挂载 |

## 13. 部署：自托管

**不依赖任何托管平台**，产物是一个 Node 进程 + 一个可写目录。完整手册见 [`自托管部署.md`](./自托管部署.md)。

```
浏览器 ──TLS──▶ nginx/Caddy ──▶ node server.js ──▶ $DATA_DIR/*.json
```

要点：

- `next.config.mjs` 开了 `output: 'standalone'`，容器里只带 `server.js` + `.next/static` + `public`，镜像约 180MB。
- 构建阶段固定 `NEXT_DIST_DIR=.next`；本地的 `.dist/.out` 那套只是为了绕开文件删除守卫，与部署无关。
- 三个必须配的变量：`PUBLIC_BASE_URL`（对外地址，决定短链与 Cookie Secure）、`ADMIN_TOKEN`（后台口令）、`DATA_DIR`（持久化目录）。
- 之前写死的 `*.blockarena.example` 已全部改为环境变量，默认按 `PUBLIC_BASE_URL` 同源推导。
- 健康检查 `/api/health`：返回数据目录可写性，`unwritable` 时给 503，供 Docker healthcheck 与反代探活。
- 部署后必跑：`ADMIN_TOKEN=xxx bash scripts/selfhost-check.sh https://你的域名`（健康、9 个页面、占位域名、调试页、鉴权三态、安全头）。

单实例限制：文件存储没有跨进程锁，**不要起多副本**；要横向扩容先把 `lib/json-store.ts` 换成数据库。
