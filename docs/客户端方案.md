# 电脑端 EXE 与 Android APK 方案

> 目标：复用现有 Next.js Web 与 Rust API，不重写业务 UI；桌面端和 Android 端只做薄原生壳，补齐系统能力。

## 0. 已确定的前提

- 支持 Windows + macOS。
- 不上架应用商店，直接分发 EXE / DMG / APK。
- 不做离线模式；客户端远程加载线上站点。
- Android 推送使用**个推**。
- 暂无 Windows 代码签名证书；macOS 签名/公证也需要单独确认。

## 1. 总体架构

```
Windows EXE（Tauri 2 / WebView2） ─┐
Android APK（Capacitor / WebView） ┼── HTTPS ──> Next.js Web + Rust API
浏览器 ────────────────────────────┘                ├─ PostgreSQL
                                                    └─ $DATA_DIR/uploads
```

- Web 仍是唯一 UI 与业务逻辑来源。
- 桌面端、Android 端加载线上站点，原生层只负责窗口、文件、通知、下载、更新、深链。
- v1 不做离线包；离线需要静态导出或本地服务，另立阶段。

## 2. 桌面端（Windows EXE）

- Tauri 2 + WebView2。
- 窗口最小尺寸、单实例、托盘、关闭到托盘。
- 系统通知、资源下载（保存对话框 + 进度）、外链交给系统浏览器。
- 自动更新：Tauri Updater + 签名清单；NSIS 安装包。
- macOS：Tauri 同时产出 `.app` / `.dmg`，分 Apple Silicon 与 Intel 两个构建。
  - 有 Apple Developer ID 时做签名 + notarization，用户体验最好。
  - 没有证书时 Gatekeeper 会拦截，用户需要右键打开或手动移除 quarantine；
    直接分发可以跑，但不适合大规模用户。
- Windows 无签名证书：SmartScreen 会提示未知发布者；可先用自签名/不签名过渡，
  但每次更新仍可能提示，建议后续补 OV/EV 证书。
- 深链：`blockarena://...`。
- 安全：原生 command 白名单，禁止任意 shell 与全盘文件访问。
- 发布：Windows 代码签名证书；GitHub Actions 构建 EXE。

## 3. Android 端（APK）

- Capacitor + 系统 WebView，`server.url` 指向线上站点。
- 只允许自己的域名导航；`cleartext=false`；发布包关闭 WebView 调试。
- 原生能力：
  - 返回键、状态栏、安全区、键盘避让
  - 系统文件选择器
  - 下载到“下载”目录 / 另存为
  - 系统分享
  - 通知与厂商推送
  - APK 应用内更新
  - 深链与 OAuth 回跳

### 3.1 文件写入策略（重点）

现代 Android 不允许随意写外部存储，按场景分四类：

| 场景 | 写入位置 | 实现 | 权限 |
|---|---|---|---|
| 草稿、缓存、日志、更新包 | App 私有目录 | `Context.filesDir` / `cacheDir` | 不需要 |
| 资源下载 | 公共“下载”目录 | `DownloadManager` | Android 9 及以下需要 `WRITE_EXTERNAL_STORAGE`，10+ 不需要 |
| 证书 / 分享图 / 截图 | 相册 `Pictures/云轨社区` | `MediaStore.Images` | 10+ 不需要；9 及以下需要写权限 |
| 用户指定位置（导出 JSON/ZIP、另存为） | 用户选择的目录/文件 | Storage Access Framework：`ACTION_CREATE_DOCUMENT` / `ACTION_OPEN_DOCUMENT_TREE` | 不需要 |
| 分享文件给其他 App | 临时文件 + FileProvider | `FileProvider.getUriForFile` + `ACTION_SEND` | 不需要 |
| 安装 APK 更新 | App 私有 `cacheDir/updates` + FileProvider | `ACTION_VIEW` + `application/vnd.android.package-archive` | 需 `REQUEST_INSTALL_PACKAGES`，用户授权“安装未知应用” |

明确不使用：
- `MANAGE_EXTERNAL_STORAGE`（所有文件访问）——应用商店审核风险高，普通社区 App 不需要。
- 直接把文件写到 `/sdcard/任意路径`——Android 10+ 会被 scoped storage 挡住。
- 让用户手动开“存储权限”才能保存——能用 SAF/MediaStore 的地方不要权限。

### 3.2 原生文件桥

新增 Capacitor 插件 `FileBridge`，只暴露必要方法：

```text
saveUrlToDownloads(url, filename)      // DownloadManager，适合资源大文件
saveImageToGallery(base64, filename)   // MediaStore，证书/分享图
saveAs({ name, mime, base64? })        // SAF，用户选位置
shareFile({ uri, mime })               // FileProvider + 系统分享
installApk({ path })                   // 应用内更新
getStorageInfo()                       // 可用空间
```

约束：
- 大文件不要走 base64 跨 JS 桥；用 `saveUrlToDownloads` 或复制 content URI。
- `saveImageToGallery` 只接受 ≤5MB 的图片。
- 所有文件名做路径穿越过滤；FileProvider 只暴露 `cache/updates` 与分享临时目录。
- WebView 仍可继续用 `<input type="file">` 选择文件上传，系统选择器返回 content URI。

### 3.3 权限清单

| 权限 | 用途 |
|---|---|
| `INTERNET` | 必需 |
| `ACCESS_NETWORK_STATE` | 弱网/重试提示 |
| `POST_NOTIFICATIONS` | Android 13+ 通知 |
| `REQUEST_INSTALL_PACKAGES` | 应用内更新 APK |
| `WRITE_EXTERNAL_STORAGE`（maxSdkVersion=28） | 仅 Android 9 及以下下载/保存 |
| `READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO` | 仅在需要直接读媒体库时；系统选择器可避免 |

- 通知权限在用户开启提醒时再请求，不要首次启动就弹。
- 更新 APK 时先检查“安装未知应用”授权，引导到系统设置。
- 隐私政策页复用站内 `/policies/privacy`。

### 3.4 应用内更新

1. `GET /api/v1/app/version?platform=android` 取版本、下载地址、是否强制、更新说明。
2. `DownloadManager` 下载到 `cacheDir/updates`。
3. FileProvider 生成 content URI。
4. `ACTION_VIEW` 安装；失败时提示用户允许“安装未知应用”。
5. 商店渠道可关闭应用内更新，交给商店。

### 3.5 推送

- 已选**个推**；客户端集成个推 SDK 获取 CID 并上报。
- 服务端凭据在 Web 后台「端管理」维护（AppID / AppKey / AppSecret / MasterSecret）。
- 国内可再叠加厂商通道，提升离线到达率。
- App 前台用 WebSocket/轮询；后台靠推送。
- 点击通知深链到帖子/约战/资源详情。

## 4. Web 端「端管理」

现已落地：

- 迁移 `0018` `app_releases`：平台（Windows x64/ARM64、macOS ARM64/x64、Android）、
  通道（stable/beta）、版本、build、下载地址、更新说明、强制更新、最低版本、SHA-256。
- 后台 `/admin/apps`：
  - 发布/编辑/删除版本
  - 发布到下载页 / 草稿
  - 强制更新、最低支持版本
  - 个推 AppID / AppKey / AppSecret / MasterSecret
- 公开接口 `GET /api/v1/app/latest?platform=android&channel=stable`。
- 公开下载页 `/download`，按 Windows / macOS / Android 分组展示最新版本。
- 导航与页脚加入「客户端下载」。

后续可加：
- 安装包直接上传（目前填下载地址，可先用对象存储/静态目录）
- 灰度发布（按 build 或用户比例）
- 更新失败率、下载量统计
- 推送发送记录与失败重试

## 5. 服务端还需要补的

- 客户端识别：`X-Client: desktop-app | android-app` 或 UA 标记，映射到现有 `Platform`。
- 能力表：App 内 `backgroundPush`、`nativeShareSheet`、`directDownload` 为 true。
- `GET /api/v1/app/version?platform=` 版本接口。
- 深链与 OAuth 回调白名单。
- 资源下载支持 Range（断点续传）可后置。
- CORS 仅本地静态包需要；远程 WebView 同源，不需要。

## 6. 分阶段

1. 契约：客户端识别、版本接口、文件桥接口、推送选型。
2. 桌面 MVP：Tauri 窗口/托盘/通知/下载/自动更新。
3. Android MVP：Capacitor 壳、返回键、安全区、文件选择、下载、SAF 另存为、分享。
4. Android 增强：推送、深链、应用内更新、OAuth 回跳。
5. 可选：离线缓存、断点续传、崩溃上报。

## 7. 风险

- 纯 WebView 壳可能被应用商店质疑，需要原生下载/推送/文件能力支撑。
- 国内推送不能只靠 FCM。
- Windows 不签名会被 SmartScreen 拦截。
- 大文件上传在弱网下体验差，后续需要断点续传。
- 远程加载无离线能力；需要离线时要改架构。
