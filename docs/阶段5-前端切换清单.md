## 3. 写路径（Server Action）——这里有个坑

页面里的 `'use server'` 表单调的是本地函数，例如 `createUser`、`addPost`、`updateSettings`。
改成 HTTP 之后，**登录/注册/登出会拿到后端的 `Set-Cookie`，但 fetch 不会把它写给浏览器**。

两种做法，按场景选：

1. **表单改成客户端 fetch**（推荐给登录、注册、登出、OAuth 入口）：
   浏览器直接 POST `/api/v1/auth/login`，经过 nginx 同源转发，`Set-Cookie` 天然生效。
   现在的登录页已经是表单提交到 Server Action，需要改成 `<form onSubmit>` 或 `action` + 客户端处理。
2. **Server Action 转发 Set-Cookie**：`apiSend` 返回 `headers`，action 里用 `cookies().set(...)` 透传。
   适合不想改前端交互的后台表单，但要多写一个 `relaySetCookie(res)` 助手。

| 现有函数 | 后端接口 | 走法 |
|---|---|---|
| `createUser` / `authenticate` | `POST /auth/register` `/auth/login` | 方案 1（要下发 Cookie） |
| `addPost` / `addComment` / `deletePost` | `POST /posts` `/{id}/comments` `DELETE /admin/posts` | 任选，无 Cookie 下发 |
| `createAgreement` / `setActive` / `removeAgreement` | `/admin/agreements` | 任选 |
| `createSlide` / `updateSlide` / `removeSlide` | `/admin/slides` | 任选 |
| `addManual` / `setHidden` / `removeManual` | `/admin/sponsors` | 任选 |
| `updateSettings` / `resetSetting` | `PATCH /admin/settings` | 任选 |
| `deletePost` | `DELETE /admin/posts?id=` | 任选 |
| `setUserBadges` | **无接口** | 见 §1 |
| `upsertSocialUser` / `linkIdentity` | 不需要 | OAuth 回调已经在 Rust 里 |
